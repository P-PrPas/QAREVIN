## Round 1

Reviewed 440a80c. P2: delivered normal alerts occupied the capacity limit indefinitely, allowing
spread flaps to block critical alerts and forward snapshots. Response: active capacity excludes
normal delivered events, repeated normal flaps coalesce for an hour, unacknowledged critical
conditions coalesce and critical alerts bypass the normal admission cap. Observer alert failures
are reported and attempt a critical integrity event while account snapshots continue.

P3 responses:
- Late delivery uses alert_send_late instead of claiming the active lease sent successfully;
  acknowledgement is idempotent, and delivery returns actual state after acknowledgement races.
- Restore requires an externally retained latest-known audit prefix and rejects older/divergent
  research histories. Owner sealed-holdout ledgers are always excluded, alongside execution and
  approval ledgers. An obsolete owner-supplied anchor cannot detect rollback: this operational
  responsibility is explicit in README.
- Execution object kinds use an allowlist, rejecting any unrelated scientific/holdout objects.
- V1 requires matching session and risk-day timezones so risk rollover cannot cut across session.
- Checkpoint source opens read-only without migrations; online snapshots are validated read-only,
  creation has streamed size limits and disk-headroom checks. Audit verification streams rows;
  observer reporting uses SQL aggregates instead of materializing all snapshots.

Regression coverage includes 1000 delivered normal alerts with critical admission, flap coalescing,
late/duplicate acknowledgement, alert-failure snapshot retention, stale/divergent audit anchors,
readonly source schema, size caps, holdout ledger exclusion, execution kinds and timezone mismatch.
